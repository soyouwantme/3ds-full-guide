# 3DS 笔记

新遇到的 3DS 流程和坑要落进项目文档，不能只留在对话里。`README.md` 是文档索引，`02-破解与自制系统.md`、`03-3DS主题安装.md` 是独立主题文档。

## 步骤

1. 判定是否值得记录
   - 记录：新流程（工具安装/使用、系统操作）、坑（失败原因、平台限制）、已验证的关键参数（IP、端口、路径、文件格式、命令）。
   - 不记录：已有文档覆盖的内容、一次性环境噪声、与 3DS 操作无关的内容。
   - 完成标准：对每个新发现明确判定记录或不记录；拿不准时先查文档。

2. 查重
   - 在项目根目录用 `rg -n "关键词" *.md` 查找已有记录。
   - 已存在：更新对应章节，不新建重复文档；完全覆盖则不改动。
   - 完成标准：确认文档中没有重复段落。

3. 确定落档位置
   - 独立主题（多步骤流程，如“安装主题”）：新建 `NN-主题.md`，`NN` 取现有文档编号最大值 + 1；同主题文件已存在则追加章节。
   - 小坑/小技巧（一句话级别，如“访达 FTP 只读”）：追加到 `01-坑与技巧.md`，文件不存在就创建，每条以日期开头。
   - 与某主题文件强相关：优先放进该文件的“坑/注意”章节。
   - 完成标准：每个新发现只落在一个位置。

4. 写记录
   - 新文件标题用 `# 3DS <主题>`；追加章节用 `## <YYYY-MM-DD> <标题>`。
   - 内容骨架：背景/现象 → 步骤（具体命令、路径、IP/端口）→ 坑/限制 → 验证结果。
   - 命令必须可直接复制；记录日期用当天；只写事实，不写推测。
   - 完成标准：仅凭文档即可重做该操作。

5. 更新 README 索引
   - 新建文件必须加入 `README.md` 的 `## 文档索引`；已有条目则更新描述。
   - 完成标准：索引里的链接实际存在。

6. 验证
   - 重读刚写的记录和 README 索引；记录里的命令能运行就实际运行验证。
   - 完成标准：记录存在、链接有效、无重复；命令已验证，或明确标注“未验证”。
