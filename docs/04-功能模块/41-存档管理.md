# 存档管理

游戏存档的备份、恢复与迁移：把「玩到一半的进度」从机器里导出来变成普通文件，需要时再导回去。3DS 破解后这完全是个文件操作问题，本文讲清存档存在哪、什么时候该备份、有哪些坑，以及推荐流程。工具的安装和按键操作见 [02-工具百科](../02-工具百科/README.md)。

## 能干什么

| 场景 | 说明 |
| --- | --- |
| 防丢备份 | 存档是机器上最经不起丢的数据（几百小时的进度），SD 卡损坏、误删游戏、系统异常都会带走它；定期导出存电脑是唯一的保险 |
| 换机 / 格式化前导出 | 换机、卖机、系统初始化、CTRTransfer 等操作前，把全部存档导到电脑，事后导回（整机级备份见 [备份与恢复](../01-系统折腾/10-备份与恢复.md)） |
| 跨版本继承 | 同一游戏换卡带版/数字版、或跨机器继续玩时，靠导出的存档衔接进度（注意下方版本/区域绑定限制） |
| 存档修改注入 | 在电脑上改好存档（如宝可梦用 PKSM 注入配信、改数值）再导回游戏；修改工具一句话带过，见工具总表 |
| 游戏更新前保险 | 大版本更新可能改存档格式，更新前先备一份，出问题可回退 |
| 跨平台/模拟器互转 | 导出的 `.sav`（如 GBA VC 选 raw 或 .sav 格式导出）是通用格式，可拿去模拟器、反向注入，也可从真卡带存档迁移 |

## 存档到底存在哪

存档位置由游戏形态决定，理解这点就知道为什么「换卡不带存档」：

| 游戏形态 | 存档位置 | 导出方式 |
| --- | --- | --- |
| 数字版 / 汉化注入版 | 跟着 title 数据走：装 NAND 的游戏在 CTRNAND，装 SD 的在 `Nintendo 3DS/<ID0>/<ID1>/title/.../data/00000001.sav` | TYSS 按 title 读取 |
| VC 游戏（GBA/GBC/SFC 等） | GBA VC 在 NAND 隐藏分区，其余在对应 title 数据里 | TYSS 支持 GBA VC（raw / .sav）与 DSiWare 存档 |
| 实体卡带 | **卡带本体**的存档芯片上，不落 SD 卡 | TYSS 读卡带 title 导出；换机时存档随卡带走，数字版才需要迁移 |
| 追加数据（DLC 进度、游戏更新补丁数据） | `extdata/` 容器 | TYSS 可单独导出 |
| 系统存档（play coins、好友列表等） | NAND `data/<ID0>/` | TYSS 支持系统存档导出（一般用不到，属整机备份范畴） |

title 数据、NAND 分区和 `Nintendo 3DS/` 目录结构的完整原理见 [3DS 原理与系统架构](../90-参考/91-原理与系统架构.md) 的「存储结构：NAND 分区与 SD 卡」与「Title 数据库与 ticket」两节。要点回顾：SD 上的 title 数据用本机密钥加密，**直接拷文件是没用的**（拷出来密文，换机也解不开），必须经存档工具走系统 FS 服务导出成明文备份；所以备份工具是这一功能的唯一入口，没有「手动拷文件」的野路子。

## 注意事项

- **备份前完全退出游戏**：存档只在游戏正常关闭时才完整写盘，游戏中或挂后台时导出/导入都可能拿到损坏数据。恢复前同样不要运行目标游戏。
- **存档与游戏版本/区域绑定**：同一游戏的不同版本（卡带版 vs 数字版、不同区域、不同汉化版）是不同的 title，存档互不通用；游戏大版本更新也可能改存档格式，旧备份恢复后可能损坏或不识别。备份时认清楚来源，养成「更新前先备份」的习惯。
- **导入是覆盖性的、不可逆**：恢复存档会把当前机器上的存档整个顶掉，导入前确认现有进度已不需要，或先反向导出一份留底。
- **备份是明文普通文件**：导出的存档可以无限复制、压缩、传电脑，但这也意味着误删即真丢——至少保留一份在电脑上，命名带日期和事由（如 `2026-01-01_系统更新前`），方便日后辨认和回溯。
- **备份做完要验证**：至少挑一个重要存档真恢复一次（可以恢复到原机器同一游戏上验证），确认备份链路是通的，别等出事才发现备份是坏的。
- **卡带和数字版别搞混**：恢复时认准来源 title，把卡带备份导进数字版（或反过来）通常不识别。
- 整机层面（NAND、movable.sed、系统数据）的备份是另一回事：那是「机器坏了能还原」的保险，本文是「游戏进度不丢」的保险，两者互补、不互相替代，见 [备份与恢复](../01-系统折腾/10-备份与恢复.md)。

## 常见误区

- **「把 `Nintendo 3DS/` 目录整个拷走就是备份存档了」**：不行。这个目录里的 title 数据是本机密钥加密的密文，离开这台机器既解不开也导不回，必须经存档工具导出明文才有意义。
- **「卸载游戏重装，存档还在吗」**：不在了。卸载 title 会连同它的存档数据一起删掉，想腾空间先导出存档。
- **「卡带游戏的存档跟着 NNID/账号走」**：3DS 没有云存档体系，卡带存档就在卡带芯片上，数字版存档就在本机存储里，唯一的「云」是你自己导出来的备份。
- **「汉化版和官方版存档通用吗」**：不一定。汉化注入版通常基于某个区域的 title，存档能否互认取决于两个 title 的存档格式是否一致，以实测为准，别默认通用。
- **「存档备份能跨机器直接用吗」**：导出后的明文备份可以随便复制，恢复到另一台机器上只要游戏版本/区域对应得上即可——这正是换机迁移的原理。
- **「恢复失败了会怎样」**：恢复前先在目标机器反向导出一份留底，最坏情况也能退回来；不留底就直接导入，等于赌博。
- **「游戏不在机器上还能备份吗」**：不能。工具是按已安装的 title 读取存档的——卡带游戏要插卡，数字版要已安装，游戏删了存档也就没了（见上文卸载那条）。

## 备份文件的管理建议

导出后的备份文件值得按一定规矩存放，否则备份越攒越乱，关键时刻找不到该用的那份：

- 电脑上建一个总目录按机器分文件夹（多台机器不要混放），每台机器下按游戏分子目录，与 `/TYSS/` 的目录结构保持一致，整目录拷入拷出即可。
- 备份命名带日期和事由（如 `20261011_换机前`），同一个游戏保留最近几份加关键节点（通关、重大更新前），太旧的定期清理。
- 存档文件都很小，zip 压缩后几乎不占空间；想要异地保险，可以把 zip 再存一份到云盘，或用 TYSS 的云端备份功能直接上传（见 [TYSS](../02-工具百科/TYSS.md)）。

## 推荐流程

以下流程以「TYSS 导出 → 电脑留存 → 需要时恢复」为主线，覆盖备份和换机迁移两个方向：



1. **安装 TYSS**：CIA 版用 FBI 装，老 3DS 机型另需 Mode3 版本；从 JKSM 迁移只需把 SD 卡上的 `JKSV` 目录改名 `TYSS`（安装方式详见 [TYSS](../02-工具百科/TYSS.md)）。老教程里的 Checkpoint 已停更，由 TYSS 取代（更替关系见 [02-工具百科](../02-工具百科/README.md) 总表）。
2. **选游戏导出**：确认游戏已完全退出，打开 TYSS 等扫描完成，按游戏逐个新建备份，存到 SD 卡 `/TYSS/` 目录（操作细节见 [TYSS](../02-工具百科/TYSS.md)）。
3. **备份到电脑**：`/TYSS/<游戏>/<备份名>/` 就是普通文件夹，用读卡器或 ftpd 无线传到电脑长期保存（无线传输见 [ftpd与文件传输](../02-工具百科/ftpd与文件传输.md)）；需要异地保险可再用 TYSS 的云端功能上传。
4. **恢复**：新机/新系统上装好游戏和 TYSS 后，把备份目录放回 `/TYSS/`，选中对应备份恢复即可——**会覆盖当前存档，动手前再确认一次**（细节见 [TYSS](../02-工具百科/TYSS.md)）。

日常节奏建议：重要进度节点（通关、拿到稀有道具）随手导一份；每次系统更新、游戏大更新、动 SD 卡内容之前，全量导出一次。
