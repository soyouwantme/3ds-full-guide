# 软件数据库与黑屏救援实录

2026-10-09/10 真实案例：系统初始化后想装 FBI，一路从"装不了软件"恶化到"开机黑屏"，最终完全修复。本篇把过程中的原理、误判和正确姿势全部固化，下次（或换一台机器）直接查这里。

## 背景与完整时间线

机器 New3DS-YJM10107872（B9S + Luma v13.4 + 官方中文版系统）做本体初期化后：

1. 初始化清空了已装软件，想重装 FBI → GM9 报 `missing one or more .db files`
2. 误判为 NAND 数据库缺失，往 NAND `dbs/` 放了 0 字节占位文件 → **开机 ARM9 崩溃**
3. 删掉占位文件后 → **开机黑屏**（电源灯亮、无画面）
4. 重跑中文安装器 → 仍黑屏（HOME 菜单已损坏，装软件救不了）
5. GM9Megascript 还原 10-08 NAND 备份 → **日文系统正常开机**，数据库完好
6. 但 GM9 装 FBI 依旧报 db 缺失；数据管理不建库；从 NAND 复制 db 到 SD 后 FBI 报 `0xD900458A`
7. 用 `fix-titledb.py` 生成加密正确的新库 → FBI 安装成功，全部软件装回，再装回中文系统

## 核心知识：3DS 有两套软件数据库

| | NAND 库（`1:/dbs/`） | SD 库（`<ID0>/<ID1>/dbs/`） |
| --- | --- | --- |
| 内容 | 机身内已装软件 | SD 卡上已装软件 |
| 存储格式 | 明文 | **用 movable.sed 加密**（AES-CTR + CMAC） |
| 缺失时的表现 | 系统可开机，装软件报错 | 系统可开机，装软件报错 |
| 0 字节文件放进去 | **开机 ARM9 崩溃**（早期挂载） | MSET9 手法，系统可按需重建 |

- FBI 等应用类 CIA **装到 SD**，GodMode9 检查的是 **SD 侧** db（`title.db`/`import.db`/`ticket.db` 三个都查，且必须非空）。报错文案里的 "Maybe the SD card is missing or uninitialized?" 就是在提示 SD 侧。
- **NAND 库和 SD 库不能互拷**：把明文 NAND 库拷到 SD，AM 读出来是乱码，FBI 装 CIA 报 `0xD900458A`（FS / Wrong argument / Desc 394）。
- 进「数据管理」**不会**重建 SD 库；SD 库由 eShop 启动 / AM 按需创建。没有 NNID 的机器等于没人帮它建，必须手动解决。

## 正确修复姿势（本机已验证）

工具在 `tools/pc/rebuild-title-database/`（材料已备齐，勿删）：

```
boot9.bin      本机的（敏感文件，勿外传）
movable.sed    从本机 essential.exefs 提取（敏感文件，勿外传）
title.db.gz    官方干净模板库
fix-titledb.py 主脚本（来自 ihaveamac/rebuild-title-database）
```

SD 卡插电脑后执行（pyctr≥0.7 已装）：

```bash
cd tools/pc/rebuild-title-database
# 先清掉 SD 里 dbs 目录下的错误文件（如从 NAND 拷来的），再运行：
python3 fix-titledb.py -b boot9.bin -m movable.sed -s /Volumes/NEW3DS
```

脚本会算出 ID0（已验证 = `e3559ec1...`）、定位唯一 ID1，写入加密正确的 `title.db` + `import.db`（各约 3.2MB）。之后 FBI/GM9 安装软件一路畅通。

注意：这适用于"库里没什么可抢救的已装软件"的场景。若要抢救 SD 上已有的已装游戏，用同仓库的 `rebuild-title-database.py` + save3ds_fuse 全流程（见 [hacks.guide 教程](https://wiki.hacks.guide/wiki/3DS:Rebuild_Title_Database)）。

## 无 FBI 时怎么装 FBI（标准姿势）

GM9 的 "Install game image" 能装 CIA，但它走自己的实现、对 db 状态挑剔。**更稳的路子是借用系统正牌 AM 服务**：

1. HOME 菜单打开「ダウンロード通信」（Download Play）
2. **L+十字键下+Select** 开 Rosalina → Miscellaneous options → **Switch the hb. title to the current app**
3. HOME 退出后再次打开「ダウンロード通信」→ 进入 Homebrew Launcher（`boot.3dsx`）
4. 运行 FBI.3dsx → `SD` → `cias` → Install

FBI 的 3dsx 版本与 cia 版本功能一致，装好后 HOME 菜单出现 FBI 图标。

## 黑屏排查决策树

```
开机黑屏、电源灯亮
├── SELECT+电源 能进 Luma 配置？
│   └── 能 → 引导层活着，问题在系统区
├── START+电源 能进 GodMode9？
│   └── 能 → 没有砖，按下面顺序救：
│       1. 重跑中文安装器（HOME 菜单损坏时这步能修；约 2 分钟，先试它）
│       2. 还不行 → GM9Megascript 还原最近一次 NAND 备份（20-40 分钟，必成功）
│   └── 不能 → boot.firm/引导问题，换已知好的 Luma boot.firm 试
└── 都不能 → 不插 SD 试；仍黑 = 引导区损坏，需 ntrboot 救砖
```

## GM9Megascript 还原的坑

- **只扫 `gm9/out/*nand_??.bin`**：备份放 SD 根目录会报 "no usable entries found"。拷进 `gm9/out/` 再跑。
- **SysNAND Restore (safe)** = 只还原 CTRNAND 主分区 + TWL，**保留** FIRM（boot9strap 安全）和控制台身份文件。
- 注意：CTRNAND 里含 `/private/movable.sed`，还原后 movable.sed 会回到备份时的版本 → **ID0 会变**：系统会新建 ID0/ID1，旧的整个作废可删（`Private/` 里的 phtcache.bin 无关，可留）。
- 还原成功后系统回到备份时状态（这次案例：日文 11.17），中文系统需用官方安装器重跑（约 2 分钟）。
- 实测 v2.2.3 脚本**不会**删除 SD 上的备份文件（旧文档记录有误，已修正）。

## 本体初期化对中文系统的影响

- 初始化会重置部分系统 title：本体設定等变回日文；HOME 菜单如果是安装器整体替换过的，可能幸存也可能损坏。
- HOME 菜单损坏的表现就是"开机黑屏但 GM9/Luma 都能进"，极易误判为引导问题。
- 结论：**初始化后先重跑官方安装器再判断机器状态**，不要急着做 NAND 还原。
- 初始化可能重新生成 movable.sed → ID0 变化，初始化后 SD 上旧 ID1 的数据（存档、extdata）即作废。

## 教训清单

1. 装软件报 db 错误，**先查 SD 侧** `<ID0>/<ID1>/dbs/`，别动 NAND。
2. 0 字节占位文件**永远不能放 NAND**；放 SD 也只是 MSET9 专用手法，GodMode9 不认 0 字节。
3. NAND 库 ≠ SD 库（加密不同），跨侧复制必失败。
4. NAND 备份是终极兜底：这次所有软件层面的折腾加起来不如一次还原。备份常备 `local/<机器编号>/nand-backup-*/`。
5. 远程指导别人（或未来的自己）在 GM9 里手动操作时，每一步给出"预期现象 + 不符就停"的判断点，避免连环误操作。
