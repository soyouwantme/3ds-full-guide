# 修改与检测序列号

序列号存在 NAND 的 `rw/sys/SecureInfo_A` 里(少数机器是 `SecureInfo_B`),不是烧死在芯片里,破解机(Luma3DS + GodMode9)可以改。

## 原理:文件格式与序列号规则

GM9 路径:`[1:] SYSNAND CTRNAND` → `rw` → `sys` → `SecureInfo_A`

`SecureInfo_A` 共 273 字节:

| 偏移 | 大小 | 内容 |
| --- | --- | --- |
| 0x000 | 0x100 | RSA-2048 签名(任天堂签名;Luma3DS 开机不校验,改了也能用) |
| 0x100 | 1 字节 | **区域码**:0=日 1=美 2=欧 3=澳 4=国行(神游) 5=韩 6=台 —— **千万别动** |
| 0x101 | 1 字节 | 固定 0 |
| **0x102** | **0xF(15)字节** | **ASCII 序列号,不含校验位** ← 改这里 |

序列号规则(见 [3dbrew Serials](https://www.3dbrew.org/wiki/Serials)):

- 格式:机型字母 + 区域字母(部分地区还有第三字母)+ 8 位数字;**第 9 位校验位由系统按 UPC 算法自动补上**,所以系统设置里显示 9 位数字。
- 机型前缀:3DS=`C`,3DS XL=`S`,2DS=`A`,New 3DS=`Y`,New 3DS XL=`Q`,New 2DS XL=`N`。
- 区域字母:日本=`JE/JF/JH/JM`,美版=`W`,欧版=`EE/EF/EH/EM`,韩版=`KF/KH/KM`,神游=`CF/CH/CM`,澳版=`AF/AH/AG/AM`。

参考:[3dbrew SecureInfo_A](https://www.3dbrew.org/wiki/Nandrw/sys/SecureInfo_A)

## 修改方法

前置条件:Luma3DS + GodMode9,改前先做备份(GM9 里 HOME → 备份,SysNAND 或至少 Essential)。

### 方法 A:SecureInfo_C 覆盖法(推荐,安全可逆)

原理:Luma3DS 检测到 `rw/sys` 下有 `SecureInfo_C` 时,开机就用它替代 `SecureInfo_A`,并跳过签名校验(见 [Luma3DS 源码 patcher.c](https://github.com/LumaTeam/Luma3DS/blob/master/sysmodules/loader/source/patcher.c))。原文件不动,想还原删掉 C 即可。

1. 长按 **Start** 开机进 GodMode9。
2. 导航到 `[1:] SYSNAND CTRNAND` → `rw` → `sys`(找不到就对该盘按 **R+A** 搜索 `SecureInfo`)。
3. 在 `SecureInfo_A` 上按 **Y** 复制 → 回到同目录按 **Y** 粘贴 → **Choose new name** → 改名为 `SecureInfo_C`(覆盖同名)。
4. 把 `SecureInfo_C` 拷到 SD 卡,电脑上改号(推荐用下方"一键改号脚本",或 Hex Fiend / HxD 手改)。
5. 手改时:跳转到偏移 **0x102**,把 15 字节 ASCII 序列号改成"2 个字母 + 8 位数字",**长度与原来保持一致**,末尾填充字节别动;`0x100` 区域码、`0x101` 绝对不碰。
6. 存盘后拷回 SD → 在 GM9 里覆盖回 `1:/rw/sys/SecureInfo_C`(会提示解锁写权限,按屏幕提示的按键组合确认)。
7. 重启进系统,系统设置 → 主机信息确认新号。
8. **还原**:GM9 里删掉 `SecureInfo_C` 重启。

### 一键改号脚本(推荐):tools/pc/change_serial.py

免手操十六进制编辑器,只改 0x102 处序列号字段、其余字节(含区域码)一律不动:

```bash
cd ~/Desktop/3DS
python3 tools/pc/change_serial.py gm9/out/SecureInfo_C QJH99887766 gm9/out/SecureInfo_C.new
mv gm9/out/SecureInfo_C.new gm9/out/SecureInfo_C
```

- 新号规则:2~3 个字母 + 8 位数字,长度最好和原号保持一致。
- 脚本会打印:原序列号、区域码(确认未动)、校验位、系统设置预计显示的完整号。
- 还原原号:`python3 tools/pc/change_serial.py <原始SecureInfo备份> <原序列号> <输出文件>`,生成原号文件再覆盖回 `SecureInfo_C`。
- 修改后文件签名失效属正常现象,仅 Luma3DS 下有效。

### 方法 B:GM9 自带十六进制编辑器

不想用电脑时:在 `SecureInfo_A`(或做好的 `SecureInfo_C`)上按 **A** → **Show in Hexeditor** → 再按 **A** 进入编辑模式 → **按住 A + 十字键**改字节 → 确认。偏移和内容同上。

### 校验位计算(UPC 算法)

第 9 位数字由前 8 位算出,想要特定尾号时自算:

```python
def check_digit(digits):  # digits = 8 位数字字符串
    d = [int(c) for c in digits]
    v = (3 * sum(d[1::2]) + sum(d[0::2])) % 10
    return 0 if v == 0 else 10 - v
print(check_digit("40456777"))  # -> 2,完整号 CW404567772
```

## 如何判断是否被改过

### 方法一:和破解时的备份对照

`essential.exefs`(GodMode9 的 Essential Files 备份)里存有破解时写入的原始 `SecureInfo`,可作为基准。用 GodMode9 或 PC 端工具从 `essential.exefs` 里导出原始 SecureInfo,解析出存储序列号(偏移 0x102 起 15 字节)、区域码(0x100)和机型前缀,留档保存。

**操作**:系统设置 → 主机信息 → 序列号;等于基准完整号 = 没改过,不等于 = 改过(对比即可知道改成了什么)。

### 方法二:GM9 查 `SecureInfo_C`

长按 Start 进 GM9 → `[1:] SYSNAND CTRNAND` → `rw` → `sys`,存在 `SecureInfo_C` 就说明用过覆盖法(改序列号或改区)。按 A → Show in Hexeditor 读 0x102 处内容与基准号对比。

注意:**转区(CTRTransfer)流程本身也会生成 `SecureInfo_C`**,有 C 文件 ≠ 一定改了序列号,要看里面内容。

### 方法三:SHA-256 对比(最严谨)

`essential.exefs` 导出的原始 SecureInfo(273 字节)是最好的基准文件,建议导出时顺手算好 SHA-256 留档:

1. 把基准文件拷到 SD 卡(如 `0:/secureinfo_orig.bin`)。
2. GM9 里分别对 SD 上该文件和 `1:/rw/sys/SecureInfo_A` 按 **A** → **Calculate SHA-256**。
3. 一致 = SecureInfo 没被动过;不一致 = 被动过(含当年直接改 A 文件的情况)。

### 方法四:格式自查(不看备份先猜)

- 前缀必须对得上机型:New 3DS XL 应为 `Q` 开头,日版第二字母为 `J`(`QJH...`)。
- 正常号 = 字母 + 8 位数字(存储),显示时 9 位;长度不对、乱码、全数字 = 改过。

## 注意事项

- **原厂(未破解)系统改不了**:签名校验会失败;只在 Luma3DS 下有效。
- 改 NAND 文件有变砖风险:务必先做 NAND / Essential 备份,只动 `0x102` 那一段。
- **改序列号 ≠ 解封**:联机封禁与 LFCS / 主机标识 / NNID 绑定,与序列号无关;解封要换 LFCS,不是序列号。
- 别用别人的真实序列号;自己随便编一组即可。
- 备份是"某时刻"快照:二手机器如果卖家在破解后、备份前就改过号,备份里也是改后的号;此时**机身贴纸**才是唯一原厂依据。
- `SecureInfo` 与 `movable.sed`、`boot9.bin` 同级属敏感文件,不要外发/上传。
